# Hyperf 3.1

**Hyperf** — это высокопроизводительный, гибкий фреймворк корпоративного уровня для PHP CLI, работающий на базе передового сервера корутин ([Swoole](https://github.com/swoole/swoole-src) или [Swow](https://github.com/swow/swow)) и множества проверенных в продакшене компонентов.

Помимо многократного превосходства традиционных PHP-FPM фреймворков в бенчмарках, уникальность Hyperf заключается в фокусе на гибкости и компонуемости. В Hyperf встроен контейнер внедрения зависимостей с поддержкой AOP (аспектно-ориентированного программирования), благодаря чему любые компоненты и классы легко заменяются и расширяются. Все ключевые компоненты Hyperf строго следуют стандартам [PSR](https://www.php-fig.org/psr) и могут использоваться даже вне фреймворка.


## Архитектура Hyperf

Архитектура Hyperf построена на мощной комбинации современных концепций:
* **Корутины (Coroutines)** — асинхронный неблокирующий ввод-вывод с синхронным стилем написания кода;
* **Внедрение зависимостей (Dependency Injection)** — мощный DI-контейнер с автосвязыванием и фабриками;
* **События (Event Dispatcher)** — управление событиями по стандарту PSR-14;
* **Аннотации и атрибуты (Annotations / Attributes)** — удобное декларативное конфигурирование (PHP 8.1+ атрибуты);
* **AOP (Aspect-Oriented Programming)** — перехват методов классов без модификации их исходного кода.

Помимо базовых корутинных клиентов для MySQL и Redis, Hyperf из коробки предоставляет корутино-совместимые версии следующих компонентов:
* **Серверы и клиенты**: WebSocket, JSON-RPC, gRPC, HTTP-клиент (Guzzle);
* **Трассировка и метрики**: Zipkin, Jaeger (OpenTracing), Prometheus;
* **Service Governance**: Consul, ETCD, Nacos, Eureka;
* **Центры конфигурации**: Apollo, Aliyun ACM, ETCD, Nacos;
* **Очереди сообщений**: Redis Queue, RabbitMQ (AMQP), Kafka, NSQ, Nats;
* **Надежность и отказоустойчивость**: Rate Limiter (Token Bucket), универсальные пулы соединений (Connection Pool), Circuit Breaker (предохранитель), Retry;
* **Утилиты**: Snowflake ID генератор, Crontab (с точностью до секунды), пользовательские изолированные процессы (Custom Processes).

При этом Hyperf остаётся привычным PHP-фреймворком со всеми необходимыми инструментами:
* Полноценная цепочка посредников (**Middleware**);
* Оптимизированная для корутин **Eloquent ORM** (включая автоматический кэш моделей `Model Cache`);
* Валидация (**Validation**), локализация (**Translation / I18n**);
* Шаблонизаторы (**Blade, Smarty, Twig, Plates, ThinkTemplate**);
* Файловая система (**Flysystem**), сессии и многое другое.


## Цели проектирования

> **Hyperspeed + Flexibility = Hyperf**

Формула в названии отражает главные амбиции проекта:

1. **Сверхскорость (Hyperspeed)**: Благодаря корутинам Swoole и Swow, Hyperf способен выдерживать экстремальные нагрузки при минимальном потреблении ресурсов памяти и CPU.
2. **Гибкость (Flexibility)**: DI-контейнер Hyperf является одним из самых продвинутых в экосистеме PHP. Классы легко заменяются через механизм `dependencies` или AOP-аспекты, позволяя строить сложные корпоративные системы без хаков.

Hyperf отлично подходит для создания:
* Высоконагруженных Web-сервисов и REST API;
* API-шлюзов (API Gateway);
* Микросервисной архитектуры любой сложности;
* Игровых серверов и сетевых сервисов реального времени (WebSocket/TCP);
* Систем интернета вещей (IoT).


## Готовность к продакшену

Hyperf был протестирован и закалён в боевых условиях крупными интернет-компаниями задолго до публичного релиза. Начиная с 2019 года, на Hyperf работают критически важные сервисы с миллионным RPS.
