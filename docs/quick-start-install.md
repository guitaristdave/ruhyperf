# Установка Hyperf

## Системные требования

Hyperf предназначен для работы в средах **Linux** и **macOS**. Если вы работаете на Windows, разработку можно вести с помощью Docker (Docker Desktop for Windows). Для пользователей macOS рекомендуется локальная установка компонентов (без монтирования через Docker volumes), чтобы избежать замедления времени запуска Hyperf из-за механизма виртуализации диска macOS.

Готовые Docker-образы доступны в репозитории [hyperf/hyperf-docker](https://github.com/hyperf/hyperf-docker) и на Docker Hub: [hyperf/hyperf](https://hub.docker.com/r/hyperf/hyperf).

Если вы настраиваете окружение вручную без Docker, убедитесь, что соблюдены следующие системные требования:

* **PHP >= 8.1**
* Один из поддерживаемых корутинных сетевых движков:
  * Расширение **[Swoole](https://github.com/swoole/swoole-src) >= 5.0** (в файле `php.ini` обязательно должна быть директива `swoole.use_shortname = Off`)
  * Расширение **[Swow](https://github.com/swow/swow) >= 1.4**
* Расширение **JSON**
* Расширение **Pcntl** (обязательно при использовании Swoole)
* Расширение **OpenSSL** (если требуются HTTPS / TLS)
* Расширение **PDO** (для работы с базами данных MySQL / PostgreSQL)
* Расширение **Redis** (для работы с Redis)
* Расширение **Protobuf** (если используется gRPC-сервер или клиент)

## Установка Hyperf

Hyperf использует [Composer](https://getcomposer.org) для управления зависимостями. Перед установкой убедитесь, что в системе установлен актуальный Composer 2.

### Создание проекта через `Composer`

Официальный шаблон [hyperf/hyperf-skeleton](https://github.com/hyperf/hyperf-skeleton) содержит стартовую структуру проекта с предустановленными базовыми компонентами и конфигурационными файлами. Во время создания проекта интерактивный установщик предложит выбрать нужные вам компоненты.

Выполните команду для создания проекта в текущей директории:

**На базе движка Swoole:**
```bash
composer create-project hyperf/hyperf-skeleton
```

**На базе движка Swow:**
```bash
composer create-project hyperf/swow-skeleton
```

> **Совет:** Во время интерактивной установки, если вы не уверены в назначении какого-либо компонента, просто нажимайте `Enter` (выбирая вариант по умолчанию). Это позволит избежать ситуаций, когда проект не запускается из-за добавления слушателей без необходимой конфигурации.

### Разработка в Docker

Если ваше локальное окружение не удовлетворяет системным требованиям или вы не хотите компилировать Swoole/Swow вручную, можно запустить готовый контейнер Docker:

#### 1. Запуск контейнера
В примере ниже локальная директория хоста `/workspace/skeleton` монтируется внутрь контейнера в `/data/project`:

```bash
docker run --name hyperf \
  -v /workspace/skeleton:/data/project \
  -p 9501:9501 -it \
  --privileged -u root \
  --entrypoint /bin/sh \
  hyperf/hyperf:8.1-alpine-v3.18-swoole
```

> Если в Docker включен SELinux, доступ к локальным файлам из контейнера может блокироваться. Параметры `--privileged -u root` гарантируют необходимые права доступа.

#### 2. Создание проекта внутри контейнера
```bash
cd /data/project
composer create-project hyperf/hyperf-skeleton
```

#### 3. Запуск сервера
```bash
cd hyperf-skeleton
php bin/hyperf.php start
```

После этого проект будет доступен по адресу `http://127.0.0.1:9501`, а исходный код можно редактировать на хосте в `/workspace/skeleton/hyperf-skeleton`.

> **Важно помнить:** Поскольку Hyperf является долгоживущим CLI-приложением, при изменении кода необходимо перезапустить процесс: нажмите `Ctrl + C` в консоли и снова выполните `php bin/hyperf.php start` (либо используйте компонент [Watcher](watcher) для автоматического Hot Reload).

## Несовместимые расширения PHP

Поскольку Hyperf работает в корутинном окружении Swoole/Swow, некоторые расширения PHP, перехватывающие стек вызовов или использующие глобальное не-потокобезопасное состояние, несовместимы:

* `xhprof`
* `xdebug` *(начиная с PHP 8.1+ и Swoole >= 5.0.2 поддержка Xdebug добавлена)*
* `blackfire`
* `trace`
* `uopz`
