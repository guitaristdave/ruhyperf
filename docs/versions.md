# Версионирование (Versions)

## Правила формирования номеров версий

Hyperf строго следует семантическому версионированию по схеме `x.y.z`:
- **x (Major)**: Мажорная версия. Выпускается при масштабных архитектурных изменениях ядра фреймворка или при наличии значительного количества обратно несовместимых изменений API (Breaking Changes). Переход на новую мажорную версию требует следования руководству по миграции.
- **y (Minor)**: Минорная версия. Выпускается при добавлении крупных функциональных возможностей или изменении отдельных публичных интерфейсов, которые могут потребовать точечной адаптации пользовательского кода.
- **z (Patch)**: Патч-версия (полностью обратно совместимая). Содержит исправления ошибок, закрытие уязвимостей безопасности, а также добавление новых вспомогательных функций и компонентов, не нарушающих работу существующего кода.

## Обновление приложения

При обновлении на новую версию `z` (патч) достаточно выполнить команду:

```bash
composer update "hyperf/*" -o
```

Рекомендуется всегда обновлять все компоненты Hyperf одновременно для сохранения согласованности версий. При переходе между минорными (`y`) или мажорными (`x`) версиями обязательно ознакомьтесь с соответствующим руководством по обновлению в разделе [Инструкции по обновлению](upgrade-3.1.md).
