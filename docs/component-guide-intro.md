# Руководство по разработке компонентов (Предисловие)

Чтобы помочь разработчикам создавать качественные компоненты для Hyperf и вместе развивать экосистему фреймворка, создано это руководство.

Перед началом разработки компонентов настоятельно рекомендуется внимательно ознакомиться с документацией Hyperf, в особенности с главами о [корутинах](coroutine.md) и [внедрении зависимостей (DI)](di.md). Без глубокого понимания этих базовых концепций легко допустить ошибки при разработке корутинных библиотек.

## Зачем разрабатывать отдельные компоненты для Hyperf?

В классическом PHP под управлением PHP-FPM при необходимости подключить стороннюю библиотеку мы просто устанавливаем её через Composer. Однако в Hyperf приложение является постоянным процессом в памяти (resident memory), а код выполняется внутри корутин. Это накладывает специфические ограничения на жизненный цикл объектов и работу с глобальным состоянием. 

Далеко не каждая библиотека из экосистемы PHP может безопасно работать в корутинном окружении без адаптации (например, из-за использования статических свойств классов или блокирующего ввода-вывода). Это руководство объяснит, как определять пригодность библиотек и как правильно адаптировать их для Hyperf.

## Организация рабочего места разработчика

Для удобной разработки компонентов рекомендуется клонировать проект скелета приложения [hyperf/hyperf-skeleton](https://github.com/hyperf/hyperf-skeleton) и репозиторий библиотеки компонентов [hyperf/hyperf](https://github.com/hyperf/hyperf):

```bash
# Установка базового скелета
composer create-project hyperf/hyperf-skeleton

# Клонирование репозитория компонентов (замените на ваш форк)
git clone git@github.com:hyperf/hyperf.git
```

Структура каталогов:

```
.
├── hyperf
│   ├── bin
│   └── src
└── hyperf-skeleton
    ├── app
    ├── bin
    ├── config
    ├── runtime
    ├── test
    └── vendor
```

Чтобы изменения в компонентах сразу применялись в скелете, настройте локальный путь к репозиторию в `hyperf-skeleton/composer.json`:

```json
{
    "repositories": {
        "hyperf": {
            "type": "path",
            "url": "../hyperf/src/*"
        }
    }
}
```

Затем удалите `composer.lock` и `vendor` в скелете и выполните обновление:

```bash
cd hyperf-skeleton
rm -rf composer.lock && rm -rf vendor && composer update
```

Composer автоматически свяжет пакеты через символические ссылки (symlinks) с исходным кодом в папке `hyperf/src/*`. Проверить это можно командой `ls -l vendor/hyperf/`.

Теперь при редактировании кода в IDE вы можете сразу тестировать компонент внутри работающего приложения и затем отправлять Pull Request в основной репозиторий Hyperf.
