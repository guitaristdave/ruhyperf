# Жизненный цикл (Lifecycle)

Понимание жизненного цикла Hyperf имеет решающее значение для правильного проектирования сервисов и избежания утечек данных и памяти.

---

## 1. Жизненный цикл фреймворка

Hyperf построен поверх событийной модели корутинного сервера **Swoole** (или **Swow**). 

### Этапы инициализации:

1. **Запуск CLI-процесса**:
   Управление консольными командами по умолчанию обеспечивает компонент [symfony/console](https://github.com/symfony/console). При вызове команды `php bin/hyperf.php start` управление передается классу `Hyperf\Server\Command\StartServer`.
2. **Инициализация DI-контейнера**:
   Контейнер внедрения зависимостей не привязан жестко к ядру фреймворка. Он инициализируется во входном скрипте через вызов `config/container.php`, что позволяет при необходимости заменить его реализацию.
3. **Сканирование аннотаций и генерация AOP-прокси**:
   Фреймворк анализирует классы проекта, собирает метаданные атрибутов и компилирует прокси-классы для аспектов (AOP).
4. **Запуск процессов Master, Manager и Worker**:
   В соответствии с конфигурацией в `config/autoload/server.php` стартует сетевой сервер Swoole, поднимая процессы Worker для обработки сетевых событий.

---

## 2. Жизненный цикл запроса и корутины

При поступлении каждого сетевого подключения или HTTP-запроса движок Swoole автоматически создает **новую корутину** (в обработчиках событий `onRequest`, `onReceive`, `onConnect`).

Таким образом:
* **Каждый входящий запрос выполняется в собственной независимой корутине.**
* Внутри запроса разработчик может порождать дочерние корутины (с помощью функций `go()` или `co()`).
* Все корутины одного рабочего процесса (Worker) разделяют одну область оперативной памяти процесса.
* Порядок переключения корутин определяется планировщиком (Scheduler) по мере выполнения операций I/O (чтение из сокета, обращение к БД или Redis).
* Корутины независимы друг от друга: между ними нет иерархических отношений «родитель-потомок».
* Передача и изоляция состояния между корутинами запроса осуществляется через специальный механизм — **[Контекст корутины (Coroutine Context)](coroutine)**.
