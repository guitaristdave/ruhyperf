# Планирование релизов (Release Planning)

## Жизненный цикл версий (Life Cycle)

| Версия | Статус | Окончание основной поддержки | Окончание поддержки исправлений безопасности | Дата релиза (или ориентировочная дата) |
| :---: | :---: | :---: | :---: | :---: |
| **3.1 (LTS)** | **Основная поддержка** | 2026-01-01 | 2027-01-01 | 2023-12-01 |
| 3.0 | Поддержка безопасности | 2023-11-30 | 2024-06-30 | 2023-01-03 |
| 2.2 | Устаревшая (Deprecated) | 2022-06-20 | 2023-11-30 | 2021-07-19 |
| 2.1 | Устаревшая (Deprecated) | 2021-06-30 | 2021-12-31 | 2020-12-28 |
| 2.0 | Устаревшая (Deprecated) | 2020-12-28 | 2021-06-30 | 2020-06-22 |
| 1.1 | Устаревшая (Deprecated) | 2020-06-23 | 2020-12-31 | 2019-10-08 |
| 1.0 | Устаревшая (Deprecated) | 2019-10-08 | 2019-12-31 | 2019-06-20 |

- **Основная поддержка (Mainstream support)**: регулярные итерационные циклы, исправление багов, улучшение безопасности и добавление новых возможностей.
- **Поддержка безопасности (Security fixes support)**: только исправление критических уязвимостей безопасности.
- **Устаревшие версии (Deprecated)**: развитие и поддержка полностью прекращены. Рекомендуется как можно скорее обновиться до актуальной версии согласно руководству по обновлению.

## Итерационный цикл выпуска версий

Разработка Hyperf ведется по гибкой методологии (Agile). Новые версии выпускаются еженедельно по **понедельникам (UTC/GMT+08:00)** — как правило, патч-релизы `z` или минорные релизы `y`. Для мажорных версий `x` сроки определяются по мере завершения этапов исследований и рефакторинга.

Правила версионирования описаны в разделе [Версионирование (Versions)](versions.md).
