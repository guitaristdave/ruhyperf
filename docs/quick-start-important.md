# Важные правила программирования в Hyperf

Перед началом разработки на Hyperf крайне важно усвоить специфику работы в корутинной среде и долгоживущем процессе (CLI daemon).

---

## 1. Запрет на использование суперглобальных массивов

В традиционном `PHP-FPM` каждый запрос запускает скрипт с нуля и изолирован в отдельном процессе. Параметры запроса получаются из суперглобальных переменных: `$_GET`, `$_POST`, `$_REQUEST`, `$_SESSION`, `$_COOKIE`, `$_SERVER`.

В **Hyperf** и **Swoole** один процесс обслуживает множество параллельных запросов в виде корутин. Использование `$_GET`, `$_POST` и других суперглобальных переменных **категорически недопустимо**, так как данные между запросами перемешаются!

Все данные текущего запроса получаются исключительно через внедряемый объект `$request` ([RequestInterface](request)).

---

## 2. Объекты из DI-контейнера являются синглтонами (Singleton)

Все классы, получаемые через контейнер внедрения зависимостей (включая контроллеры, сервисы, репозитории), по умолчанию создаются **в единственном экземпляре на весь жизненный цикл процесса (Worker)**.

Это означает:
* Экземпляр контроллера или сервиса разделяется между миллионами запросов и множеством параллельных корутин.
* **Свойства объектов не должны содержать состояние текущего запроса!**
* Нельзя сохранять `User`, `Request`, `Response` или пользовательские ID в свойства класса (`$this->user = $user` — это грубая ошибка, которая приведет к утечке чужих данных в другие запросы).

Любые данные, специфичные для запроса, должны передаваться через аргументы методов либо сохраняться в **контексте корутины** ([Coroutine Context](coroutine)).

---

## 3. Оптимизация для продакшена (scan_cacheable)

При развертывании в продакшене обязательно включайте кэширование аннотаций и прокси-классов.

В файле `config/config.php`:
```php
'scan_cacheable' => env('SCAN_CACHEABLE', true),
```

Когда включен `scan_cacheable = true`, Hyperf генерирует прокси-классы AOP и кэш атрибутов один раз при первом запуске (или при сборке Docker-образа). При последующих перезапусках этап сканирования пропускается, что в разы ускоряет запуск и снижает расход памяти.

Поскольку сканирование пропускается, Hyperf полагается на оптимизированную карту классов Composer. Поэтому перед запуском в продакшене необходимо выполнить:

```bash
# Оптимизация карты классов Composer
composer dump-autoload -o

# Прогрев кэша прокси-классов и атрибутов
php bin/hyperf.php
```

> **Внимание:** В среде разработки (на локальной машине) значение `scan_cacheable` должно быть `false`, иначе изменения в аннотациях не будут подхватываться.

---

## 4. Избегайте переключения корутин в магических методах

Не рекомендуется выполнять операции ввода-вывода (I/O, запросы к БД, HTTP, таймеры), вызывающие переключение корутин, внутри магических методов `__get`, `__set` и `__isset` (за исключением `__call` и `__callStatic`). 

Внутренние оптимизации PHP при обращении к свойствам могут привести к неожиданному поведению при асинхронном переключении стека внутри `__isset` или `__get`.
