# Корутины в Hyperf (Coroutines)

## Концепция корутин

Hyperf построен на базе корутин **Swoole** (и **Swow**). Это ключевой фактор, обеспечивающий экстремально высокую производительность и масштабируемость фреймворка.

### Модель работы PHP-FPM

В традиционной архитектуре `PHP-FPM` используется многопроцессная модель `FastCGI`. Веб-сервер (например, Nginx) принимает HTTP-запросы и передает их мастер-процессу PHP-FPM, который выделяет под каждый запрос один рабочий процесс (Worker Process).

В этой модели:
* Каждый процесс Worker синхронно и полностью блокируется на время выполнения скрипта: ожидает компиляции, ожидает ответа от MySQL, Redis, внешних HTTP API.
* Количество одновременно обрабатываемых запросов строго ограничено количеством запущенных процессов PHP-FPM. Если запущено 200 Worker-процессов, и каждый запрос занимает 1 секунду (например, из-за внешних API или сложных выборок), то максимальный теоретический RPS системы равен всего `200 req/sec`.
* Каждый Worker держит отдельное TCP-соединение с базой данных MySQL, что быстро исчерпывает пул подключений к БД (`max_connections`).

---

### Асинхронная неблокирующая модель vs Корутины

В асинхронной неблокирующей модели один процесс может параллельно обрабатывать тысячи запросов: как только запрос инициирует сетевой ввод-вывод (I/O), управление возвращается циклу событий (Event Loop), и процесс занимается другими задачами, не простаивая.

Однако классический асинхронный код на функциях обратного вызова приводит к **Callback Hell** (аду колбэков):

```php
// Пример старого стиля Swoole 1.x на колбэках:
$db->connect($config, function ($db, $r) {
    $db->query('SELECT * FROM users WHERE id = 1', function($db, $r) {
        $db->query('UPDATE users SET name = "new" WHERE id = 1', function ($db, $r) {
            // Множество уровней вложенности
        });
    });
});
```

В других языках эту проблему решали через `Promise`, `async/await` или генераторы (`yield`). Но даже с `async/await` разработчик вынужден постоянно помечать функции ключевыми словами и помнить о синтаксических нюансах.

**Корутины Swoole / Swow решают эту проблему наиболее элегантным способом:**
* Вы пишете обычный, привычный, синхронный PHP-код:
  ```php
  $user = User::query()->where('id', 1)->first();
  $redis->set('user:1', json_encode($user));
  ```
* На низком уровне движок автоматически перехватывает сетевые вызовы (Hook I/O) и невидимо для разработчика переключает корутину на время ожидания ответа сокета.
* Никаких ключевых слов `await` или `yield` в коде писать не требуется!

## Что такое корутина?

**Корутина (сопрограмма, Coroutine)** — это легковесный поток выполнения, управление и переключение которого осуществляется в пространстве пользователя (userland), а не ядром операционной системы.

* В рамках одного процесса Worker в любой момент времени фактически исполняется **ровно одна корутина**.
* Переключение происходит мгновенно (за доли микросекунды) без тяжелого контекстного переключения на уровне ядра ОС.
* Так как в одном потоке одновременно выполняется только одна корутина, отсутствует необходимость в классических блокировках потоков (мьютексах), характерных для многопоточного программирования.

Когда корутина A отправляет запрос в MySQL, планировщик переводит её в состояние ожидания I/O и переключает выполнение на корутину B. Когда ответ от сетевого сокета для корутины A получен, планировщик возобновляет выполнение корутины A с того места, где она была приостановлена.

## Особенности корутинного программирования

### 1. Недопустимость блокирующего кода

Если внутри корутины вызывается блокирующая синхронная операция (например, системный `sleep()`, блокирующий `curl` без поддержки Swoole Hook, или синхронные вызовы сторонних расширений C), весь процесс Worker заблокируется, и другие корутины не смогут выполняться!

> Hyperf по умолчанию активирует `Swoole Hook All`, что автоматически делает большинство стандартных функций PHP (включая PDO, Redis, stream_select, sleep) неблокирующими. Однако всегда следует использовать корутинные клиенты Hyperf (Guzzle с корутинным адаптером, встроенные клиенты Redis/MySQL).

### 2. Запрет хранения состояния в глобальных переменных

Поскольку миллисекундный контекст Worker-процесса разделяется между сотнями параллельных запросов-корутин, **нельзя использовать**:
* Суперглобальные массивы `$_GET`, `$_POST`, `$_SESSION`, `$_SERVER`;
* Статические свойства классов для хранения данных пользователя (`User::$current`);
* Свойства синглтон-сервисов для сохранения параметров конкретного запроса.

Для хранения состояния текущего запроса используйте **Контекст корутины** (`Hyperf\Context\Context`).

## Использование корутин в коде

### 1. Создание корутины

Для запуска фоновой корутины используются хелперы `co()`, `go()` или фабричный метод `Coroutine::create()`:

```php
use function Hyperf\Coroutine\co;
use function Hyperf\Coroutine\go;
use Hyperf\Coroutine\Coroutine;

// Способ 1
co(function () {
    // Код выполняется в отдельной корутине
    Coroutine::sleep(1);
    echo "Корутина завершена\n";
});

// Способ 2
go(function () {
    // Логика корутины
});
```

### 2. Проверка корутинного окружения

```php
use Hyperf\Coroutine\Coroutine;

if (Coroutine::inCoroutine()) {
    $cid = Coroutine::id(); // Идентификатор текущей корутины (int)
} else {
    // Код запущен вне корутины (например, в скрипте инициализации)
}
```

### 3. Каналы связи (Channel)

`Channel` (аналог каналов в Go) служит для безопасной передачи данных между корутинами без сетевых задержек:

```php
use Hyperf\Coroutine\Coroutine;
use Swoole\Coroutine\Channel;

co(function () {
    $channel = new Channel(1); // канал емкостью 1 элемент

    co(function () use ($channel) {
        // Производитель данных
        $channel->push(['message' => 'Привет из дочерней корутины!']);
    });

    // Потребитель ожидает данные
    $data = $channel->pop();
    var_dump($data);
});
```

* `push()`: помещает данные в канал. Если канал заполнен, корутина приостанавливается до освобождения места.
* `pop()`: извлекает данные. Если канал пуст, корутина ждет появления данных.

---

### 4. Функция Defer

Функция `defer()` регистрирует колбэк, который гарантированно выполнится в самом конце жизненного цикла корутины (по принципу LIFO — последним вошел, первым вышел):

```php
use function Hyperf\Coroutine\defer;

co(function () {
    defer(function () {
        echo "Выполнится третьим (LIFO)\n";
    });
    defer(function () {
        echo "Выполнится вторым\n";
    });

    echo "Выполнится первым\n";
});
```

---

### 5. Ожидание завершения группы корутин (WaitGroup)

Аналог `sync.WaitGroup` из Go. Позволяет запустить несколько задач параллельно и дождаться их завершения в главной корутине:

```php
use Hyperf\Coroutine\WaitGroup;
use function Hyperf\Coroutine\co;

$wg = new WaitGroup();
$wg->add(2); // Ожидаем 2 корутины

co(function () use ($wg) {
    // Тяжелая операция 1
    $wg->done();
});

co(function () use ($wg) {
    // Тяжелая операция 2
    $wg->done();
});

// Ожидаем завершения обеих задач
$wg->wait();
```

---

### 6. Параллельное выполнение задач (Parallel)

Компонент `Parallel` в Hyperf — это удобная надстройка над `WaitGroup`, возвращающая результаты работы задач:

```php
use Hyperf\Coroutine\Parallel;
use function Hyperf\Coroutine\parallel;
use Hyperf\Coroutine\Coroutine;

// Вариант с классом:
$parallel = new Parallel();
$parallel->add(function () {
    Coroutine::sleep(1);
    return 'Результат 1';
});
$parallel->add(function () {
    Coroutine::sleep(1);
    return 'Результат 2';
});
$results = $parallel->wait(); // [0 => 'Результат 1', 1 => 'Результат 2']

// Лаконичный вариант через хелпер parallel():
$results = parallel([
    'user' => function () {
        return User::query()->find(1);
    },
    'orders' => function () {
        return Order::query()->where('user_id', 1)->get();
    },
]);

// Запросы к пользователю и заказам выполнятся параллельно всего за время самого долгого из них!
```

### 7. Контекст корутины (Coroutine Context)

Для безопасного хранения состояния запроса используется класс `Hyperf\Context\Context`:

```php
use Hyperf\Context\Context;

// Сохранить значение в контексте текущей корутины
Context::set('auth_user_id', 42);

// Получить значение
$userId = Context::get('auth_user_id', default: null);

// Проверить наличие
if (Context::has('auth_user_id')) {
    // ...
}
```

Контекст привязан к текущей корутине и **автоматически очищается** по её завершении. Память освобождается, и утечки данных между пользователями полностью исключены.
